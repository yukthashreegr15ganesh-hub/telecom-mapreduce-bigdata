🏗️ End-to-End System Architecture

A reproducible, fault-tolerant distributed pipeline running over authentic Milan Call Detail Records:

1
Data Ingestion
Harvard Dataverse (DOI: 10.7910/DVN/EGZHFV). 322.87 MB raw CDR dataset with MD5 verification.
2
HDFS Storage Layer
Distributed block storage on Apache Hadoop 3.4.0 HDFS managed via persistent Linux systemd daemons.
3
Hadoop MapReduce
Streaming Python MapReduce with In-Mapper Combining. Aggregates cells, intervals, and international codes.
4
Analytics & Anomaly Engine
Spatial Gini index, Pareto analysis, and non-parametric Median & MAD anomaly detection models.
5
Streamlit Dashboard
Low-latency (8.28 ms) interactive telemetry deployed on Streamlit Community Cloud.

Architectural Disclosure & Academic Integrity
  • Single-Node Execution: The MapReduce aggregation was executed in a pseudo-distributed single-node host via Hadoop LocalJobRunner against persistent HDFS block storage. It is not a multi-node cluster.
  • Dataset Temporal Scope: Consistent with project parameters, this pipeline processes Day 1 (2013-11-01, containing 4,842,625 records). The remaining 61 daily files were not ingested.
  • Dimensionless Traffic Indices: Volume values represent proportional density indices normalized by Telecom Italia to preserve commercial secrecy and subscriber confidentiality.
  • Statistical Anomaly Scope: The 56 detected anomalies reflect statistical variance in CDR traffic volume (surges, commuter spikes, transit clusters) and do not represent confirmed physical telecommunications hardware failures.
